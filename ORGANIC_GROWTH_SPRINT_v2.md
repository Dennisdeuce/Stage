# ORGANIC GROWTH SPRINT v2 — PNW Stage

> **Provenance:** the originally referenced v2 document was not present in this
> repository, its git history, or any reachable source. This version was
> authored in-session (2026-07-05) from the repo's actual state and committed so
> the sprint has a single tracked source of truth. Amend freely — the execution
> log at the bottom records what has actually shipped.

**Goal:** grow organic (unpaid) discovery and repeat usage of PNW Stage — the
zero-backend PNW concert & comedy finder — without breaking the $0/month
budget or the no-API-server architecture.

**Constraints (inherited from BUILD_SPEC):**
- $0/month: free tiers only; no paid tools, ads, or services.
- Zero backend: SPA + Supabase read-only + GitHub Actions cron. Anything
  "server-side" must be build-time (Actions) or client-side.
- ToS-clean: primary ticket links only, TM attribution, no scraped prose.

## Phase 1 — Discoverability foundations

### 1.1 Technical SEO & sharing baseline  ← **this sprint's starting point**
Code-only, no sign-offs, no cost. Make the one URL we have index and unfurl
correctly.

- [x] Canonical URL + full Open Graph / Twitter-card meta in `index.html`.
- [x] Social share image (`/og.png`, 1200×630) generated by a stdlib-only
      script (`web/scripts/make_og.py`) in the same style as `make_icons.py`.
- [x] `public/robots.txt` (allow all, sitemap pointer) and
      `public/sitemap.xml` (root URL; grows in 1.2).
- [x] `schema.org` structured data:
      - static `WebSite` JSON-LD in `index.html`;
      - runtime `ItemList` of `MusicEvent`/`ComedyEvent`/`TheaterEvent`
        JSON-LD injected from live events (`web/src/lib/seo.ts`) so
        JS-executing crawlers see the actual inventory.
- [x] Per-tab `document.title` sync (Feed / Calendar / Venues).
- [x] PWA manifest polish: `id`, `lang`, `categories`.
- [x] E2E coverage: new spec asserting canonical/OG meta, the runtime
      ItemList JSON-LD, and per-tab titles.
- [x] Drive-by fix: the calendar's year button rendered as literal
      "multiMonthYear" (`buttonText.year` doesn't apply to a custom
      `multiMonthYear` view) — now labeled "Year"; calendar spec locators
      made strict-mode-safe (`exact: true`).

Base URL is the Cloudflare Pages default `https://pnw-stage.pages.dev`
(single constant in `web/src/lib/seo.ts`, mirrored in `index.html`,
`robots.txt`, `sitemap.xml`). A custom domain is a Decision Queue item; when
signed off it's a four-file find-and-replace.

### 1.2 Deep links & prerendered pages ✅ shipped
Give search engines and sharers more than one URL.

- [x] Path-based deep links for individual events and venues
      (`/e/<id>-<slug>`, `/v/<venue_slug>`), opening the existing drawers
      (`web/src/lib/routes.ts`). The open event owns the URL path; closing
      returns to `/`. Event links to expandable metros (Portland/Vancouver)
      auto-reveal the expander. Cloudflare Pages serves prerendered stubs at
      these paths when they exist and falls back to the SPA shell otherwise.
- [x] Build-time prerender step in the deploy workflow
      (`web/scripts/prerender.mjs`, zero-dep): emits static HTML stubs
      (title/description/OG/canonical/JSON-LD per event & venue) from the
      public Supabase views at deploy time so non-JS crawlers and unfurlers
      get real content. Skips itself gracefully if env/fetch is unavailable —
      it can never break a deploy.
- [x] `sitemap.xml` regenerated at deploy time from the same payload
      (root + every event + every venue URL).

### 1.3 Performance & Core Web Vitals ✅ shipped
- [x] Self-host the three Google Fonts (latin + latin-ext woff2 subsets in
      `public/fonts/`, `src/fonts.css`): no render-blocking third-party
      requests, no font CDN privacy leak. Space Grotesk deduped to one
      variable-font file per subset (Google's 400/500/700 were identical).
      Above-the-fold faces (`Anton`, `Space Grotesk`) get `<link rel="preload">`.
- [x] Replace the `picsum.photos` poster fallback with a local branded
      placeholder SVG — the last third-party runtime request is gone; the app
      is now fully self-contained except for event images and ticket links.
- [x] `decoding="async"` on poster images (cards were already `loading="lazy"`;
      card/drawer art is absolutely positioned in fixed-size boxes, so no CLS).
- [x] PWA precache now includes fonts/SVG/PNG — full offline shell.

## Phase 2 — Shareability & retention ✅ shipped
- [x] "Share" action on the event drawer (Web Share API, clipboard fallback
      with a "Link copied" confirmation) using §1.2 deep links
      (`web/src/lib/share.ts`).
- [x] "Add to calendar" — client-generated RFC 5545 `.ics` per event
      (`web/src/lib/ics.ts`): timed events when a start time is known
      (2h default duration), all-day otherwise; escaped/folded text; ticket
      link + deep link in the description. No server involved.
- [x] Public RSS 2.0 feed of shows first seen in the last 7 days at
      `/feed.xml`, generated in the prerender step and advertised via
      `<link rel="alternate">` + a footer link. The scrape workflow now
      triggers a deploy after each successful nightly run, so the feed —
      and the prerendered stubs and sitemap — refresh daily (zero new infra).
